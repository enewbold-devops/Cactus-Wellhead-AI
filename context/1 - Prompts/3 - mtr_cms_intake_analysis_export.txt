ASSISTANT RESPONSE 1
------------------------------------------------------------
Absolutely — for MTR/MTC packages (Mill Test Report / Material Test Certificate) tied to CMS (Cactus Master Specification) material types, the file types and attachment formats matter a lot because they determine:

- whether the data is machine-readable (searchable text / tables),
- whether you can auto-validate chemistry/mechanical/Charpy/HT/hardness rules,
- and how reliably you can traceability-link heats, lots, and part/PO lines.

1) The “real world” attachment types you’ll receive
A. PDFs (most common)
Variants:
1) Text-based PDF (best): generated from Word/ERP/QMS (searchable, selectable text).
2) Scanned PDF (common): image-only pages inside a PDF container (not searchable).
3) Hybrid PDF: scanned pages with an OCR text layer (sometimes messy alignment).
4) PDF portfolio / multi-doc binder: one PDF containing many certificates, charts, and stamps.
Typical issues: rotated pages, skew, faint stamps, handwritten edits, mixed units, multiple heats in one table.

B. Office documents (DOC/DOCX, XLS/XLSX)
DOC/DOCX: certificate templates with typed values + signature blocks.
XLS/XLSX: chemistry + tensile + impact tables; good if true tables.
Typical issues: merged cells, multiple tables, hidden rows/cols, macros, printed-to-PDF later.

C. Images (JPG/PNG/TIFF/HEIC)
Sources: phone photos, screenshots, tags/labels, stamping, bundle photos.
TIFF: older QMS/scanner format.
HEIC: common from iPhone.
Typical issues: perspective distortion, glare, low resolution, missing corners, multi-page photos.

D. “Package” formats (ZIP, MSG/EML)
ZIP: full MTR package with separate files.
MSG/EML: forwarded email with embedded attachments.

E. Structured data exports (rare but ideal)
CSV, XML, JSON, EDI-style cert data. Best for validation + ingestion.

2) What to require vs what to accept (policy)
Preferred: text-based PDF (or PDF/A), clean XLSX, digitally signed PDF.
Accepted: scanned PDFs, images, DOCX templates.
Conditional/discouraged: password PDFs, low-res images, photo-PDFs without normalization, partial screenshots.
Not accepted: risky formats; certs missing traceability identifiers regardless of type.

3) Format expectations inside the files (what varies)
Common blocks: header, heat/lot mapping, chemistry table, mechanical properties, Charpy, heat treatment, hardness, signatures/stamps.
Most parsing failures happen in tables; Charpy varies widely (temp/specimen/orientation/avg vs single).

4) CMS-type-specific attachment patterns
Forgings/bar/plate: PDF MTR with chemistry/tensile/impact + HT summary + traceability statement.
Castings: MTR + HT chart or NDE report; multiple attachments per lot.
Elastomers/seals: often COC + lab sheet (PDF/XLSX).
Coatings/plating: COC + process cert + bath analysis; sometimes gauge reading images.

5) Normalization strategy
Normalize incoming evidence into:
1) Original immutable archive
2) Normalized view copy (PDF/A, deskewed, rotated, OCR)
3) Extracted data artifact (JSON: heat/grade/chem/mech/Charpy/HT/hardness)
4) Traceability index links (Supplier → PO → line → heat/lot → parts/serials → CMS type)

6) Supplier/customer attachment rules
- Prefer one heat/lot per certificate (or clearly separated sections).
- PDF searchable text preferred; scans at ≥300 dpi.
- Include spec/grade, heat/lot, PO + line, chemistry, mechanical, impact (if required), HT condition, hardness (if required).
- Use file naming convention: Supplier_PO_Line_Heat_Spec_Rev_CertNo.pdf
- For images: no glare; full page; heat/lot readable.

- Step flow: context → upload → confirm detected structure → submit for processing
- Edge rules: allow PDF/DOCX/XLSX/CSV/images/ZIP/MSG/EML; block unknown/risky; size/page limits; virus scan; flag encrypted PDFs

3) Architecture separation
Layer 1: secure landing + immutable archive (hash, metadata, chain-of-custody)
Layer 2: normalization (PDF/A view copy, per-page images, OCR text layer, table candidates)
Layer 3: document classification (MTR vs COC vs HT vs NDE vs coating vs packing list)
Layer 4: extraction + validation + review

4) Normalization details
- Text PDF: extract embedded text/structure
- Scanned PDF: rasterize pages; deskew/denoise/binarize; OCR
- DOCX: extract text/tables; export PDF view copy
- XLSX: parse tables; also export PDF view copy
- Images: orientation/crop/deskew; run layout detection prior to OCR
- ZIP/MSG/EML: unpack/enumerate/classify/normalize each file

5) Classification
Use layout + keywords + supplier template fingerprinting.
Drive doc-specific extraction (better than generic OCR).

6) Extraction (manufacturing schema)
Canonical schema: material identity, traceability, chemistry, mechanical, Charpy, heat treatment, hardness, conformance statements.
Extraction modes:
- table extraction (chem/mech/impact)
- key-value extraction (heat/cert/PO)
- section parsing (HT notes)
- stamp/signature presence detection

Security: malware scan, encryption, segregation, retention.
